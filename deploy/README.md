# Deployment examples

These files are templates. The installer is still the supported path for the
privileged helpers:

```bash
sudo scripts/install_privileged.sh --user "$USER" --units "nginx"
```

## MCP server as a systemd service

`linux-agent-mcp.service` runs the Streamable HTTP transport on loopback. Before
installing it:

1. Create the service account and place the checkout in its home, or edit
   `User`, `Group`, `WorkingDirectory` and `ExecStart`.
2. Put `GROQ_API_KEY` in `/etc/linux-agent/agent.env` (mode `0600`) if the
   server itself needs to call the model. The MCP server normally only serves
   tools, so the key belongs to the client host instead.
3. Keep `LINUX_AGENT_ALLOW_WRITE=0` unless you deliberately want the service to
   expose write tools. The human approval gate lives in the CLI, not in the
   server.

```bash
sudo install -o root -g root -m 0644 deploy/linux-agent-mcp.service \
    /etc/systemd/system/linux-agent-mcp.service
sudo systemctl daemon-reload
sudo systemctl enable --now linux-agent-mcp.service
systemctl status linux-agent-mcp.service
```

`systemd-analyze verify deploy/linux-agent-mcp.service` reports the example
`ExecStart` path as missing until you replace the placeholders.

## sudoers

`sudoers.linux-agent.example` documents the rule generated by
`scripts/install_privileged.sh`. Prefer the installer: it validates the file
with `visudo -cf` before installing it as `root:root 0440`. The rule allows only
the two root-owned helper scripts; it does not grant general sudo access.
